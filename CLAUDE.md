# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Hoshikawa — The Offline Valley: a Godot 4.6.2 Mono (C# / .NET 8) action-JRPG prologue. Single outdoor map, one playable character (Mio), three patrol robots, ten NPCs across two villages.

## Commands

```sh
just run                      # build C#, import assets, launch (the whole loop)
just run -- --play            # skip the title screen
just unit                     # gdUnit4Net unit tests, plain .NET
just self-test                # build, import, in-engine self-test in English, then Japanese and Traditional Chinese
just e2e                      # build, import, godot-e2e tests
dotnet build Hoshikawa.csproj # C# only
```

`just run` uses `GODOT_MONO`, defaulting to `/Applications/Godot_mono.app/Contents/MacOS/Godot`. The plain `godot` on PATH is a **non-Mono** build and will not run this project. `GODOT_MONO` is not exported in the shell, so set it before running the raw `$GODOT_MONO` commands below: `export GODOT_MONO=/Applications/Godot_mono.app/Contents/MacOS/Godot`. Likewise `blender` is not on PATH; use `/Applications/Blender.app/Contents/MacOS/Blender`.

`.claude/worktrees/` holds full checkouts of other branches (excluded via `.git/info/exclude`). Ripgrep skips them; plain `grep -r`/`find` will return duplicate hits from them.

### Tests

Three suites, all C#. CI (`.github/workflows/`) runs the unit tests on every push and PR, and the self-test plus e2e tests on PRs and by manual dispatch. CI is headless Linux only: GitHub's runners have no GPU and software Vulkan draws the valley at well under 1 fps, so graphical runs stay a local Metal job.

- **Unit** (`tests/unit/`, `just unit`): gdUnit4Net (`[TestSuite]`, `[TestCase]`, `AssertThat`) on plain .NET against the game assembly, with no engine running. Only static data and pure functions work there (`World.Height`, `RoadX`, the `Hamlet` table, `Prologue`, files under `assets/`); nodes, `GD`, and native singletons such as `Geometry2D` or `RandomNumberGenerator` need the engine, so behaviour that touches them belongs in the self-test or e2e.
- **E2E** (`tests/e2e/`, `just e2e`): gdUnit4Net tests that launch the game as a separate headless Godot process through godot-e2e (`addons/gdunit_e2e/`, not versioned — CI downloads the pinned cwchanap/godot-e2e release zip (`GODOT_E2E_VERSION` in `e2e.yml`, mirrored by `e2e_addon_version` in the justfile) and `just e2e` fetches it when missing or stale; never edit the copy here, fix upstream and bump the pin). Tests reach nodes by path (`/root/Hoshikawa`, `/root/Hoshikawa/Mio`) and read C# fields by name (`Mode`, `QuestStage`, `Speaker`); keys, frame waits and vectors go through the raw commands in `tests/e2e/Hoshikawa.cs`. The child finds Godot through `GODOT_BIN`, which `just e2e` sets from `GODOT_MONO`. A failing test leaves its scene tree and logs in `test_output/csharp/<suite>/<test>/` (no screenshot headless). Each test pays a full game start, about eight seconds.
- **Self-test** (`just self-test`): `scripts/IntegrationCheck.cs`, the main suite, a single async method that runs inside a real Godot instance, injecting input and asserting against the actual controllers and physics:

```sh
dotnet build Hoshikawa.csproj
$GODOT_MONO --headless --editor --path . --import      # required after any asset change
$GODOT_MONO --headless --path . --fixed-fps 60 -- --self-test
```

Passing prints `SELF_TEST_PASS` and exits 0; failing prints `SELF_TEST_FAIL <exception>` and exits 1. Each assertion logs `CHECK <message>`.

The self-test runs in English unless `--lang=ja` or `--lang=zh_TW` follows `--self-test`; those runs replay the whole flow with that language on screen, and the closing checks (glyphs, fixed-width boxes, line breaking, language buttons, `Localization.Missing` empty) are what catch a string without a translation. Run all three before pushing text changes; CI does.

To run a subset, comment out or early-return within `IntegrationCheck.Run` — assertions are sequential statements, not discoverable cases, and later ones depend on earlier player placement. Prefer adding checks next to the related ones rather than at the end.

Run it **both** headless and graphically (drop `--headless`); several past defects only appeared under the Metal renderer. `project.godot` selects the **Mobile** rendering method on Metal, not Forward+, so check a rendering feature is supported there before relying on it. Under a graphical run, OS focus changes release injected input — `Frames()` re-presses held actions and logs `TEST_INPUT_RESTORE`, so don't "fix" a flake by removing that.

A `NU1900` NuGet audit-endpoint warning on build is expected and not a regression.

## Architecture

**The entire game is built in C# at runtime.** `scenes/Main.tscn` is six lines: a `Node3D` with `scripts/Game.cs` attached. There are no other game scenes, no editor-authored nodes, no autoloads, and no `.tres` resources; godot-e2e's `addons/gdunit_e2e/runtime/bootstrap.tscn` is loaded only by e2e test processes. Do not reach for the Godot editor to add content — add it to the constructing code.

- `Game.cs` — root `Node3D`. Owns `GameMode` (Title/Playing/Dialogue/Paused/Defeated), quest stage and objective text, the camera rig (`Node3D` → `SpringArm3D` → `Camera3D`), lock-on, dialogue, toasts, effects (`Burst`/`Slash`/`FloatingNumber`), audio, screenshots, and the input map. `InputBindings()` registers every action in code — `project.godot` has no `[input]` section.
- `World.cs` — deterministic environment and both villages. Nothing here is random at runtime (`rng` is seeded 2189), and its only per-frame work is turning the water wheel and bobbing the moored boat. `Terrain()` builds the 1 m ground over the play area and its 40 m margin (`World.Fine`) in 64 m chunks under one `Terrain collision` body, the 4 m mountains and seabed around it to `World.Far`, and a skirt between the two that spans both meshes' edges.
- `Wilds.cs` — `partial class World`: everything beyond the play area. `Outside()` is `Height()` there: the edge's own ground carried outward (its channels filled within 12 m, so none runs on as a trench), up an 8–12 m cliff into the mountains, down a beach under the south-west sea (`Sea()`, with rocky `Capes`), or through a river's gorge (`Rivers`), whose walls open into a valley where it runs deep. `WaterGrid()` lays the sea and each gorge reach on the terrain's own grid, 1 m or 4 m, `Waterfall()` hangs a curtain (`waterfall.gdshader`) at each fall, and `Walls()` lists the only invisible walls: one off the beach and one behind the Cedar River canyon's boulder choke.
- `Architecture.cs` / `Hamlet.cs` — `partial class World`. `Architecture.cs` holds the curved-roof generator (`Roof`, `RoofY`, now only the shrine's) and `Minka()`, which places each Hoshikawa style's Tripo model (`workshop`, `kura`, `hall`, `teahouse`, `clinic`, `farmhouse`) from `TripoHouses` (model origin, walls rectangle, sign position): a walls box and the model's own faces below 2.4 m on layer 1, the whole mesh as camera-only eaves, the shop sign on cords from the eave, and the teahouse's and clinic's extras. `Hamlet.cs` holds the brook, footbridge, terrace wall, shrine, `StoneLantern()`, the Tripo props both villages share (`Well()`, `NoticeBoard()`, `Handcart()`, `Kakashi()`, the scarecrow) with their colliders, the `Hasa()` rack and the village `Dressing()`. `World.Komorebi()` places its five houses through the same `Minka()`.
- `Player.cs` / `Enemy.cs` — `CharacterBody3D` controllers holding all action timing as float countdowns ticked in `_PhysicsProcess` (attack, dodge, guard, deflect window, posture, stun, invulnerability, cooldowns). Combat tuning lives inline in these two files; there is no data/config layer.
- `Prologue.cs` — every line of the prologue's visual-novel scenes as `(Speaker, Text)` beats; a blank speaker is narration. `Game.Play(beats)` starts a scene, `Advance()` finishes a typing line or moves on, `EndDialogue()` returns to play. Quest stages still change on `Interact()`, before the scene plays. `Begin()` (title screen) plays the intro; `Start()`, which the self-test calls, does not. Every scene is a named array in `SceneNames` (the key `<scene>.<beat>` that voice files and translations share), including the one-beat repeats (`RenReminder`, `RelayGuardedFor(left)`, `Usual(name)`); a resident's repeated line is the first beat of their first meeting. Never build an ad hoc `Play((speaker, text))`: it has no key, so it is neither translated nor voiced.
- `Localization.cs` — English, Japanese and Traditional Chinese. Code, quest state (`Objective`), `Speaker`, `Script` and scene names stay English; only what is drawn is translated, at draw time. Dialogue is `Line(scene, beat, english)` from `assets/dialogue/<lang>.json`; interface text is `T("English")` / `F("{0} template", args)` from `ui.<lang>.json`, keyed by the exact English string, and is also registered with `TranslationServer` so `Label3D` and `Button` text translates itself.
- `ActorVisual.cs` — thin `AnimationPlayer` wrapper. Finds the animator under an imported GLB, normalizes clip names (`some/path/run.001` → `run`), and sets loop modes. Every character goes through it; `Play(clip, speed, restart)` is the only animation entry point.
- `Hud.cs` — a single `Control` drawn entirely in `_Draw()` (immediate mode). Title screen, vitals, minimap, dialogue and perilous-attack diamond are draw calls, not nodes; `Game._Process` calls `QueueRedraw()` each frame. Menus are the one exception: `RefreshMenu()` builds real `Button` nodes, including the language buttons. Dialogue wraps with `TextParagraph`, which knows where Japanese and Chinese may break; the typewriter reveals characters, at a slower rate for CJK. In `GameMode.Dialogue` the HUD draws only the visual-novel layer: portraits from `assets/art/portraits/<name>.png` (lower case, no hyphen; a missing file just leaves the slot empty), Zero's link emblem, and the text box.

### Text and languages

Anything the player can read goes through the translation tables, or the self-test fails in `--lang=ja` and `--lang=zh_TW`.

- A new `Toast`/`Feedback`/`Label3D`/`Button` text, HUD string or resident role: pass the English text and add the same key to **both** `assets/dialogue/ui.ja.json` and `ui.zh_TW.json`. HUD draw calls wrap the string in `T(...)` (or `F(...)` for a `{0}` template, never an interpolated string). Signs use the capitals the code shows (`KISARAGI WORKSHOP`). A unit test fails on a key missing from either file, a key the code no longer uses, and mismatched `{0}` placeholders.
- A new or edited prologue line: add it to `Prologue.cs` as a named scene, then to `ja.json` and `zh_TW.json` with `en` equal to the English (the unit tests and `tools/build_voice.py --check` refuse stale entries), and note any new name or term in `assets/dialogue/glossary.md` first. Keys are positions, so inserting a beat shifts every later key and its voice file.
- A character in a translation that the fonts lack draws as a box: run `python3 tools/build_fonts.py` (fontTools plus `apt install fonts-noto-cjk` or the Noto CJK `.ttc` files) and re-import. The self-test lists any missing character.
- Layout is fixed-width: the self-test measures the menu buttons, the controls and objective panels and the toast panel in every language, so a longer translation fails there rather than overflowing.
- Voice is Japanese under all three languages; `Prologue.Unvoiced` names the scenes that deliberately have no mp3.

### Invariants worth knowing before editing the world

1. **`World.Height(x, z)` is the single source of truth for terrain.** The visible mesh, its trimesh collider, and every placement call read the same static function, so geometry and collision cannot drift. Placing anything means calling `Height()` — never hardcode a Y. Adding a landform means editing `Height()`, which moves collision with it. Inside the play area (`World.InPlay()`, |x| ≤ 64, z −200…80) it is `Inside()`; beyond, `Outside()` in `Wilds.cs`, which starts from the edge's own height so the two meet without a step. The water is the exception: the `Hoshikawa river` sheet (z −12…−4), the `Cedar River` sheet (z −114.75…−107.25) and the brook strip are fixed planes at `World.WaterLevel` and `World.CedarLevel` whose edges must stay buried in the river dip and bank in `BaseHeight()`, the Cedar River's slot through the hill, and the brook channel in `HamletGround()`. Reshape those and the edges surface; `IntegrationCheck` requires ≥ 4 cm of burial, just above the water shader's 3.5 cm wave. The brook's mouth row reuses the river sheet's edge vertices, because the wave is computed per vertex and any other spacing opens a step at the joint. Both river sheets are 128 m of 1 m cells, so at x ±64 they meet the gorges' and the sea's water on the same columns; the wave depends on x alone, so a joint along a line of constant x never opens. Every water mesh runs `water.gdshader`, which reads the depth texture for shallow-to-deep colour, the shore fade and foam; each material sets its own `flow`. The terrain's vertex red is dryness, `1 - World.Shore()`, which `terrain.gdshader` paints as wet earth and gravel at the waterlines and on the paddy floors; vertex green is 0 beyond the play area, keeping the road's paint off the beach.
2. **`World.RoadX(z)` and `assets/shaders/terrain.gdshader` describe the same road curve in two languages.** Change one and you must change the other, or the painted road separates from the placement guide; `TerrainTest` reads the shader's constants and fails when they drift. The same applies to `RegionAt()`'s Z thresholds and the region names used in `Game._Process` toasts and the HUD minimap.
3. **Hoshikawa's layout is data.** The `World.Hamlet` table (name, centre, size, yaw, style) drives the levelled house pads inside `Height()`, the `Minka()` buildings, the shrubs and the stepping stones. Its size is the walls' width and depth (X, Z) and the front eave's height (Y), which the sign cords reach; each style's model must stay inside the pad's 1.6 m level apron, so resize the table rather than offsetting a model. Move a house by editing the table, never one placement. `World.KomorebiHouses` places Komorebi's five houses in the same shape and sizes; Komorebi's ground is level within |x| < 29 and z −182…−132, so it has no pads, and its meeting hall closes the road's north end. `World.Paddies` likewise drives the level paddy floors inside `Height()`, the aze levee mesh `RiceFields()` lays over them, each paddy's still water and the rice. `World.BrookX(z)` is shared by the `Height()` channel, the water strip, the footbridge and the minimap line; `World.Footpaths` by the footpath strips, the shrub clearance and the grass exclusion.
4. **Seeded streams are pinned.** The countryside and northern valley draw from `rng` (seed 2189), and `IntegrationCheck` pins the first boulder's exact position. Hoshikawa's dressing draws only from `villageRng` (seed 3301), Komorebi's courtyard shrubs and persimmons from their own generator (seed 5101). `Tree()` always consumes exactly three draws from whichever generator it is given, so changing a species or model never shifts later scatter. `World.Grass()` draws a field's extra tufts, blades and colours from its own seeded generator, so lawns and meadows never shift the streams their seed positions come from. The reeds, river and brook stones, rice hills, aze grass and bridge planks have generators of their own too.
5. **The valley is closed by its own ground, and its water runs downhill.** There is no box wall round the play area: beyond its edge `Outside()` raises a cliff steeper than Mio's 50° floor limit and taller than her jump, or lays a beach down into the sea, and `WildsTest.TheValleyIsClosed` floods the walkable ground from the village square and fails if it reaches more than 16 m out. The only invisible walls are `World.Walls()`, and each stands where something visible stops you (the sea, the boulder choke). The Hoshikawa springs from a hollow high on the eastern range, runs down its slope and over two falls, and crosses the valley at sea level west to the sea; the Cedar River springs from its own hollow further north, falls twice into Cedar Pass and leaves through the western canyon down its own valley to the bay. `World.Rivers` lists each course upstream first, with the water's level at each point: levels never rise downstream, a fall (`World.Fall()`) is two points under 1.5 m apart with straight reaches either side (a bend at a fall lets the upper floor show through its curtain), a steep reach may fall up to 0.7 m per cell corner to corner, and a course ends at a valley river's edge at that river's level or in the sea. Beyond the play area, water over the 1 m and 4 m ground is never a plane: `WaterGrid()` wets each terrain cell with a corner under its level, so every shore is buried by construction (only the open sea past the 4 m ground's end is a plain sheet). New water follows the same rules, and `WildsTest` checks them.
6. **Static primitives are baked.** At the end of `World._Ready`, `Merge()` bakes every box, sphere and cylinder, and every Blender prop placed with `Prop()`, under `World`'s plain `Node3D` containers into one mesh per material and 32 m cell. The originals stay, hidden, for their colliders, names and `IntegrationCheck`'s lookups. Moving or recolouring an original after `_Ready` changes nothing on screen. Anything that must change at runtime goes under a non-`Node3D` parent or is added after `_Ready`. `Mat()` returns one shared material per colour, emission and `twoSided`, which is what lets `Merge()` group by reference: never change a material `Mat()` returns. Pass `twoSided: true`, or build your own material.

Collision layers: **1** world/static geometry, **2** player, **4** enemies, **8** (`World.CameraLayer`) camera-only: roofs carry a `CameraStop()` body there so the spring arm (mask 1|8) stays under the eaves while the player and robots, which never collide with 8, walk beneath them. `World.Box(..., solid: true)` is the standard way to add a static collider alongside a mesh.

### Character assets

GLBs under `assets/models/` are **pre-exported and committed**; `editor/import/blender/enabled=false`, so Godot never touches Blender. `.blend` sources in `assets/source/` are gitignored and live only on this machine.

For new models use `python3 tools/import_character.py SOURCE --name NAME --height METRES`. It accepts `.blend/.glb/.gltf/.fbx`, preserves source files, textures and bound clips, and writes the GLB, `assets/source/NAME-game.blend`, the texture copies (`assets/art/NAME-import/` for a rigged character; `assets/source/NAME-textures/`, never committed, for a static model, whose GLB already carries them) and `artifacts/model-imports/NAME/build.json`. Existing outputs require `--force`; `--output-root` supports trial exports. Chiyo/KOMA-7 scripts and `tools/import_tripo_villagers.py` (Sora/Nao/Toma) are presets of this importer; Mio's importer, which cuts and retimes her Tripo clips and fits the sword, remains specialized. See README's import section for selection/idle/reduction options and the runnable `tools/check_character_import.py` regression check. New NPCs still need an entry in `World.TripoResidents` (asset, height, label height) and runtime checks.

- `mio.glb` — the user's low-poly Tripo model with the 65-bone Mixamo rig (prefix stripped) and 12 clips the user made in Tripo Studio (`assets/source/tripo-bridge-20261016-mio-anim.blend`), textures from the repaired `mio-lowpoly-fixed-face2.blend`, 47,980 triangles with the sword. `import_tripo_mio.py`'s `CLIPS` table cuts each Tripo action and retimes it to the game length Player.cs is tuned against; change a clip there, not in Godot. The same script adds the attack ready-stance blends, the jump crouch/tuck and the right-hand grip; Player.cs plays walk and run at ground-matched rates. Rebuilt by `/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python tools/import_tripo_mio.py`, audited by `python3 tools/check_mio_export.py`.
- `chiyo.glb` — the user's Tripo elder: 41 bones, one authored `idle` clip (the source supplied no actions), 1.58 m tall. Built by `tools/import_tripo_chiyo.py` in background Blender; source `assets/source/chiyo-tripo-original.blend` is preserved. Only Chiyo uses this GLB.
- `koma7.glb` — the user's Tripo gardener robot: 65 bones, one authored six-second head-turn `idle`, 1.25 m tall. Built by `tools/import_tripo_koma7.py` in background Blender; the original source and all 96,316 triangles/four textures are preserved. Only KOMA-7 uses it; hostile robots retain `patrol.glb`.
- `sora.glb` / `nao.glb` / `toma.glb` — the user's Tripo villagers, sent from Tripo Studio over DCC Bridge: 65 Mixamo bones (prefix stripped), one authored four-second breathing `idle` each, 1.78 / 1.64 / 1.74 m, all source triangles kept. Built by `tools/import_tripo_villagers.py` from `assets/source/{sora,nao,toma}-tripo-original.blend`. The other human NPCs (Ren, Aki, Hana, Emi, Yui) retain the shared villager rig.
- `villager.glb` / `patrol.glb` — the authored models kept on purpose: 58 bones, 12 clips. Ren, Aki, Hana, Emi and Yui use `villager.glb`; the three hostile robots use `patrol.glb`. `tools/build_characters.py` builds the patrol, then runs `tools/refine_humans.py`, which builds the villager and saves `assets/source/villager.blend`. Neither touches Mio. `assets/source/characters.blend` keeps the authored Mio scene only because `import_tripo_mio.py` takes her sword from it.

`IntegrationCheck` asserts exact bone counts (Chiyo 41, Mio/KOMA-7/Sora/Nao/Toma 65, shared humans 58), specific bone names and Mio's 12 clips. For every `World.TripoResidents` entry it also asserts the looping idle, textured material, skeleton deformation, grounding, fitted collision, idle duration and stationary hips/feet. Any re-export must keep the corresponding character's contract or the self-test fails.

Trees and shrubs (`assets/models/props/*.glb`: keyaki, sugi, sakura, bamboo, shrub and the `kaki` persimmon) have no `.blend` source. `/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python tools/build_props.py` regenerates them deterministically. They carry material *names* only (`bark_<species>`, `foliage`); `World.Tree()` binds the bark textures and `foliage.gdshader` by those names. Village props (lamp, bench, barrel, bamboo fence post and bay, field fence post and rail, brook pebbles and rock, paddy sluice, water-wheel trough and hasa rack, bridge deck plank, cabbage and daikon) come the same way from `tools/build_village_props.py`. They carry material names `cedar`, `paper`, `bark_bamboo`, `stone`, `straw`, `leaf`, `leaf_dark` and `root`, which `World.Prop()` binds to the existing atlases and colours. Don't add more: each extra material adds a merged draw in every cell a prop stands in. Complex props come from the Tripo API instead. Shrink their 4096 px maps with `tools/shrink_glb_textures.py` (and cut any stray fragment off with `tools/cut_glb.py`), then import them static with `import_character.py` under 10k triangles (20k for buildings, which are seen up close under the eaves). Place them whole, unmerged, with fitted colliders, through `World.Model()`, like `well`, `lantern`, `cart`, `notice`, `waterwheel`, `scarecrow`, `boat`, `kawabata` and the Hoshikawa and Komorebi houses (ASSETS.md records task ids, prompts and credits). `Model()` gives each model one shared, tinted copy of its material, because Tripo's albedo reads darker than the village atlas; the tint is the brightness knob. Newly imported textures default to `mipmaps/generate=false`: set it to true in their `.import` for anything that tiles or is alpha-cut.

Audio is synthesized by `python3 tools/build_audio.py` (stdlib only). Voice is different: Japanese dialogue lines come from ElevenLabs into `assets/audio/voice/ja/<Speaker>/<scene>.<beat>.mp3`, and `Game.Advance()` plays whichever file matches the beat. Follow `.claude/skills/voicing-dialogue/SKILL.md` to translate, audition or voice lines; editing a voiced line in `Prologue.cs` makes its Japanese, Chinese and audio stale. Art in `assets/art/` is imagegen output used unedited (except the chroma-keyed foliage atlas and the split bark atlas); prompts and provenance are in `ASSETS.md`, which should be updated whenever an asset is regenerated.

## Code style

The C# here is deliberately dense: file-scoped `namespace Hoshikawa;`, `ImplicitUsings` and `Nullable` enabled (`null!` for Godot-initialized fields), multiple statements per line separated by `;`, and no blank lines inside methods. Match it. Comments are rare and explain a non-obvious physical or pipeline constraint (e.g. why a jump frame index is what it is), not what the code does.

`AGENTS.md` is a symlink to this file so Codex reads the same instructions; edit `CLAUDE.md` and keep the link. `PLAN.md` tracks completed work as checklists; `README.md` documents controls, the prologue route and per-file notes for players. Both are kept current with the code.
